# 56 KV Cache 与 Context Window

> 一句话：KV Cache 把历史 Token 的 Key/Value 存起来，生成新 Token 时只算新位置、省下大量重复计算；Context Window 是模型一次能用的最大 Token 范围，不是长期记忆。

- 先读 [37-Scaled-Dot-Product-Attention](37-scaled-dot-product-attention.md)、[54-训练为什么并行-生成为什么串行](54-why-train-parallel-generate-serial.md)。

## 一、直观含义

- **KV Cache**：自回归生成时，前面每个 Token 的注意力 Key、Value 其实**算过一次就不变了**。不缓存的话，生成第 100 个字要把前 99 个字的 K、V 全部重算一遍——太浪费。缓存下来，每次只算新字，读旧缓存即可。
- **Context Window（上下文窗口）**：模型一次推理"看得见的范围"——提示词、历史对话、检索内容、已生成文本加在一起能塞多少 Token。**超出窗口的信息，模型看不到**，除非你重新给进去。

## 二、具体例子

- 生成长文：第 100 步时，KV Cache 里存着 1~99 步的 K/V，第 100 步只需算第 100 步的 Q/K/V 和注意力，直接读缓存的前 99 份 K/V。
- 对话窗口 8192：前面聊了 9000 个 Token，再发消息时最早的部分会被"挤掉"——模型已经看不到最开头说了什么了。

## 三、技术要点（严谨部分）

### 1. KV Cache（Key-Value 缓存）

- 保存历史 Token 在各层注意力中的 **Key 和 Value**。
- 生成新 Token 时，不必重新计算全部历史 K、V，**只计算新位置**并读取缓存。
- 好处：大幅减少重复计算，显著加速生成。
- 代价：随上下文长度、层数、Head 数和隐藏维度增长，**占用显存**。

### 2. Context Window（上下文窗口）

- 模型一次可利用的**最大 Token 范围**：提示词、历史对话、检索内容和已生成文本。
- 对 Decoder-only 模型，通常由**位置编码训练长度**和注意力实现共同决定。
- ⚠️ **上下文窗口不是长期记忆**：超出窗口的信息若没有被重新提供，模型无法直接访问。

### 3. Context Window 与 Memory 的区别

| | Context Window | Memory（记忆） |
|---|---|---|
| 本质 | 本次推理可见的 Token 范围 | 系统额外保存、未来重新提供的信息 |
| 来源 | 本次输入里给的内容 | 外部系统/工具/数据库 |
| 特性 | 用完即走 | 可持久化、可检索 |

> 模型不会因为一次读过内容就永久记住，除非参数被训练更新或外部系统再次提供（详见 [73-易混淆概念辨析-下](73-易混淆概念辨析-下.md)）。

## 四、一句话总结

KV Cache 是"算过一次就别再算"的缓存，省时间但吃显存；Context Window 是"这次能看多远"的上限，不是记忆——窗外的东西，模型看不见。
