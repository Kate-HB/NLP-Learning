# 61 子词标签对齐

> 一句话：一个词被切成多个子词，但只有一个词级标签——"标签对齐"决定这个标签怎么分给子词：第一个子词继承原标签、后续子词转 I 或忽略、特殊 Token 用 -100 排除。

## 一、直观含义

词的标签按"词"给，模型却按"Token"预测——中间隔着子词拆分这道墙。对齐就是搭桥：

- 一个词拆成 3 个子词 Token，但只有 1 个词级标签。
- 常见做法：**第一个子词继承原标签**，后续子词按规则转成内部标签（如 `B-PER` → `I-PER`）或直接忽略。
- 特殊 Token（`[CLS]`、`[SEP]`、PAD）不参与损失——标签设为 **-100**，交叉熵自动跳过。

## 二、具体例子

"谷歌中国"是一个 `B-ORG` 的实体，子词切分后：

```
Token:   谷歌  中国  [SEP]  PAD
词级标签: B-ORG  I-ORG  -100  -100
```

- "谷歌"是第一个子词 → 继承 `B-ORG`。
- "中国"是实体内部后续子词 → 转成 `I-ORG`。
- `[SEP]`、PAD → `-100`，不算损失。

## 三、技术要点（严谨部分）

### 1. 问题定义

- **子词标签对齐（Subword Label Alignment）**：处理"一个原始词被切成多个 Token，但只有一个词级标签"的问题。

### 2. 常见对齐思路

1. **特殊 Token 和 Padding 不参与损失**：标 `-100`（损失函数忽略）。
2. **第一个子词继承原标签**：词首子词拿完整标签（如 `B-PER`）。
3. **后续子词的处理**，按标注规范选：
   - 转为实体**内部标签**（`B-PER` → `I-PER`）——保留实体连续性信息；
   - 或直接**忽略**（标 -100）。
4. 选择哪种策略会影响**训练信号**和**评估方式**。

### 3. 工具怎么帮我们对齐

- **词 ID 映射（word_ids）**：告诉我们每个子词属于哪个词（见 [18-偏移映射与词-ID-映射](18-偏移映射与词-ID-映射.md)）。
- **词 ID 映射（word_ids）**：告诉我们每个子词属于哪个词（见 [18-偏移映射与词-ID-映射](18-offset-mapping-word-id-mapping.md)）。
- 有了它就能判断"是不是同一个词的后续子词"，从而决定继承/转 I/忽略。

### 4. 评估的对应问题

- 即使训练用 -100 忽略部分子词，**评估指标**（如 seqeval 按实体算 F1）也必须按实体边界+类别匹配，而不是只算 Token 级 accuracy（见 [69-评价指标-Accuracy-Precision-Recall-F1](69-评价指标-Accuracy-Precision-Recall-F1.md)）。
- 即使训练用 -100 忽略部分子词，**评估指标**（如 seqeval 按实体算 F1）也必须按实体边界+类别匹配，而不是只算 Token 级 accuracy（见 [69-评价指标-Accuracy-Precision-Recall-F1](69-metrics-accuracy-precision-recall-f1.md)）。

### 5. ⚠️ 注意别和"句子对齐"混淆

- 这里的"对齐"是**词标签 ↔ 子词 Token** 的坐标对齐。
- 不是翻译里的"源句 ↔ 目标句"对齐，也不是模型对齐（见 [03](03-AI-机器学习-深度学习与模型.md)）。
- 不是翻译里的"源句 ↔ 目标句"对齐，也不是模型对齐（见 [03](03-ai-ml-dl-and-models.md)）。

## 四、一句话总结

子词对齐解决"词级标签怎么分给子词"：首子词继承、后续子词转 I 或忽略、特殊/PAD 用 -100 排除——策略不同，训练信号和评估就不同。
