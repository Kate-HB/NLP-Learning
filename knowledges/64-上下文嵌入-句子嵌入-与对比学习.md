# 64 上下文嵌入、句子嵌入与对比学习

> 一句话：上下文嵌入是"结合语境"的词向量，句子嵌入是整句话的固定向量；对比学习通过"近的拉近、远的推开"专门训练出好用的句向量。

## 一、直观含义

- **上下文嵌入**：同一个词在不同句子里，向量不同——因为带了语境。"苹果"在"吃苹果"和"苹果公司"里是两个不同的向量。
- **句子嵌入**：把整句话浓缩成一个固定长度向量，用于比较"两句话像不像"。
- **对比学习**：训练句向量的方法——**语义相近的文本向量拉近，语义无关的推远**。像教一个保安"认人"：长得像的（同义）分到近处，不像的隔开。

## 二、具体例子

- 语义搜索："如何做红烧肉" 的向量和一篇"红烧肉做法"文档的向量应该很近，和"如何修自行车"很远。
- 正样本对：问题"今年夏天热吗" + 答案"今年夏天高温天气多"。
- 负样本对：问题 + 一篇无关文章。
- 难负样本：问题"如何做红烧肉" + 文档"红烧肉的做法很简单"（表面相似其实不是答案）——这类更难训练，也更有效。

## 三、技术要点（严谨部分）

### 1. 上下文嵌入（Contextual Embedding）

- 结合上下文后得到的 Token 向量。
- 同一个词在不同句子中的向量可以不同。
- 对比：初始 Token Embedding 与上下文无关（见 [34-Token-Embedding-与输入表示相加](34-Token-Embedding-与输入表示相加.md)）。
- 对比：初始 Token Embedding 与上下文无关（见 [34-Token-Embedding-与输入表示相加](34-token-embedding-input-adding.md)）。

### 2. 句子嵌入（Sentence Embedding）

- 表示整句话或整段文本的**固定长度向量**。
- 获得方式：
  - **CLS Pooling**：取 CLS Token 的最终隐藏状态作为整段表示。
  - **平均池化（Mean Pooling）**：对有效 Token 隐藏状态求平均，通常**要排除 Padding**。
  - 专门训练的句向量模型。
- ⚠️ **句子向量通常需要专门训练**，不能默认任意模型的 CLS 状态都适合语义相似度。

### 3. 对比学习（Contrastive Learning）

- 让语义相关的文本向量**靠近**，让无关文本向量**远离**。
- **正样本对（Positive Pair）**：语义应接近的文本组合，如问题与正确答案。
- **负样本对（Negative Pair）**：语义不相关或不匹配的组合。
- **难负样本（Hard Negative）**：表面上与查询很相似、实际上并不正确。它比随机无关文本更能训练模型分辨**细微语义差异**。

### 4. 训练目标与损失

- 对比学习常用 InfoNCE 类损失：让"正对"相似度远大于"负对"相似度。
- 向量在训练后常做**归一化**，用余弦相似度比较（见 [65-向量空间-相似度度量-与检索](65-向量空间-相似度度量-与检索.md)）。
- 向量在训练后常做**归一化**，用余弦相似度比较（见 [65-向量空间-相似度度量-与检索](65-vector-space-similarity-retrieval.md)）。

## 四、一句话总结

上下文嵌入带语境、句子嵌入是整句的"指纹"、对比学习靠"正近负远"专门炼句向量——这三个是语义搜索和 RAG 的地基。
