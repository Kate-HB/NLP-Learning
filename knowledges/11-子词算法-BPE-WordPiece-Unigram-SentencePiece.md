# 11 子词算法：BPE、WordPiece、Unigram 与 SentencePiece

> 一句话：四种主流子词算法用不同的"标准"决定把哪些小片段拼成大片段（或从大往小删），Tokenizer 模型 = 词表 + 这套切分规则。

## 前置知识

- 先读 [10-三种分词粒度](10-三种分词粒度.md)。
- 若想亲手推一遍 Unigram 的"选最优切分"，见 [12-动态规划与-Viterbi-算法](12-动态规划与-Viterbi-算法.md)。

## 一、直观含义

四种算法像是四套"拼图规则"：

- **BPE**：从单字开始，反复把"最常一起出现"的两块拼起来——像玩消消乐，谁相邻出现最多谁先合并。
- **WordPiece**：也从小拼大，但选择标准更讲究——它选"合并后让语料概率提升最大"的对，而不只看出现次数。
- **Unigram**：反过来，从一个大词表出发，算每个子词的重要性，逐步删掉"删了也不心疼"的，留下最有用的。
- **SentencePiece**：不是第四种"怎么拼"的算法，而是一套**不按空格切词的处理框架**——它把整段文本当字符流处理，用特殊符号表示空格，适合中文这种没有空格分隔的语言，且可以承载 BPE 或 Unigram。

## 二、具体例子

- BPE 合并过程：语料里 "low、lowest、lower" 反复出现 "lo"，先合并成 `lo`；再看到 "low" 频繁，把 `lo+w` 合并成 `low`。词表就长出了越来越大的子词。
- WordPiece 差异：`('a','b')` 出现了 100 次，但合并后对整体建模帮助不大；另一对 `('un','believable')` 只出现 5 次，却能显著降低语料困惑度——WordPiece 会选后者。
- SentencePiece 对中文："自然语言"直接当字符流处理，空格被编码成 `▁` 特殊符号，不依赖"先按空格切词"这个前提。

## 三、技术要点

### 1. BPE（字节对编码）

- 从较小单位开始，**反复合并语料中最常见的相邻单位**。
- 合并规则记录了"从字符/字节逐渐组成常见子词"的过程。
- 特点：只看频率，简单高效。GPT、Marian 等常用。

### 2. WordPiece

- 也从小单位逐步合并，但选择标准更关注**合并后对语料概率的改善**，而不只看相邻对的绝对频率。
- 特点：更"聪明"但训练更贵。**BERT 系列常使用 WordPiece**。

### 3. Unigram

- 从一个**较大的候选词表**开始，为每个子词估计概率。
- 逐步删除对整体损失影响较小的子词。
- 对一个单词分词时，寻找**总体概率最高的子词组合**（找法见 [12-动态规划与-Viterbi-算法](12-动态规划与-Viterbi-算法.md)）。
- 特点：词表可控、可解释性较好。T5、SentencePiece 常用。

### 4. SentencePiece

- 一套直接把原始文本**当作字符流处理**的分词方法框架。
- 不要求先按空格切词，用特殊符号（如 `▁`）表示空格边界。
- 因此**适合中文、日文等不依赖空格的语言**，也可以承载 BPE 或 Unigram 模型。

### 一个重要区分

- "Tokenizer 模型" = 分词算法 + 词表 + 合并/删除规则（**统计过程，确定性**）。
- "Transformer 模型" = 神经网络参数（**随机梯度下降，随机性**）。
- 两者名字都叫"模型"，但完全是两种东西（详见 [13-词表-Token-ID-与-OOV](13-词表-Token-ID-与-OOV.md) 与 [73-易混淆概念辨析-下](73-易混淆概念辨析-下.md)）。

## 四、一句话总结

BPE 按频率合并、WordPiece 按概率提升合并、Unigram 按损失影响删除、SentencePiece 是"不依赖空格"的承载框架；它们共同把"常见词整块、生僻词拆碎"落实成具体规则。
