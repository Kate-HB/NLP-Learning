# 53 Checkpoint 与 Model Card

> 一句话：Checkpoint 是某个训练时刻"冻结下来"的模型状态文件，不是运行中的模型对象；Model Card 是描述模型用途与局限的说明书。

## 一、直观含义

- **Checkpoint（检查点）**：训练中途的"存档"——权重、配置、优化器状态等打包存成一个文件。程序崩了可以从存档继续，不用从头跑。
- **Model Card（模型卡片）**：模型的"简历"——它是干什么的、用什么数据训练的、效果如何、有什么局限和偏见。

## 二、具体例子

- 训练每 500 步存一个 checkpoint，某次中断后从最近的 checkpoint 恢复。
- 用 `from_pretrained("./checkpoint-1000")` 加载保存的状态继续微调。
- 在 Hugging Face Hub 看到一个模型页，先看它的 Model Card 判断"适不适合我的任务"，而不是只看名字和下载量。

## 三、技术要点（严谨部分）

### 1. Checkpoint（检查点）

- **某一训练时刻保存的模型状态**，通常包含：权重、配置，以及恢复训练所需的信息（如优化器状态、学习率调度状态）。
- **它不是正在运行的模型对象，而是一份可加载的保存状态**。
- 典型用途：
  - 断点续训（崩溃后恢复）。
  - 保留"效果最好的那个时刻"（early stopping 时存最佳 checkpoint）。
  - 加载后继续微调或推理。

### 2. Model Card（模型卡片）

- 描述模型的：用途、训练数据、评估结果、限制、偏见、使用方法。
- 意义：帮助使用者判断**模型是否适合当前场景**，而不是只看模型名称或下载量。

### 3. 一个常见踩坑

- 训练后如果**重新创建模型对象**（重新 `from_pretrained`），classification head 会回到**随机初始化**——已训练权重丢失。
- 正确做法：train 后立即 evaluate，或从保存的 checkpoint 加载已训练权重。

## 四、一句话总结

Checkpoint 是训练状态的"存档文件"、能续训能加载；Model Card 是模型"简历"、帮你在用之前判断合不合适——一个是"怎么存"，一个是"怎么选"。
