# 28 训练/验证/测试集、泛化与数据泄漏

> 一句话：训练集用来更新参数，验证集用来挑超参数，测试集只在最后评估一次；泛化是"在没见过的数据上也能做好"；数据泄漏会让评估虚高、骗了自己。

## 一、直观含义

把数据分成三堆，像"练习册、模拟卷、高考卷"：

- **训练集**：平时练习，用来改参数。
- **验证集**：模拟考，用来挑"做题策略"（超参数、比较方案），可以反复用。
- **测试集**：高考，只在最后考一次，**原则上不能用来反复调参**——考完就作废，考过了数据就等于泄露了。

**泛化** = 换一批没见过的高考题也能考好，而不只是背下了练习册。

## 二、具体例子

- 分类任务：训练集改权重 → 验证集选学习率/轮数 → 最终在测试集报一个分数。
- **数据泄漏反例**：清洗时不小心把测试集里"该预测的答案"混进了训练数据 → 测试分数虚高，上线后真实表现崩盘。
- 常见泄漏来源：切分前先做整库归一化/统计、验证集和训练集有重复样本、用测试集反复调参。

## 三、技术要点（严谨部分）

### 1. 三集分工

- **训练集（Training Set）**：用于更新模型参数。
- **验证集（Validation Set）**：用于选择超参数、观察训练状态、比较方案，**不直接参与参数更新**。
- **测试集（Test Set）**：用于最终评估，原则上不应反复用于调参。

### 2. 泛化（Generalization）

- 模型在**未见数据**上仍能正确工作的能力。
- 它是训练的终极目标：训练集表现好 ≠ 泛化好。

### 3. 收敛（Convergence）

- 训练过程中损失和参数变化逐渐稳定。

### 4. 数据泄漏（Data Leakage）

- 验证或测试信息不恰当地进入训练过程，导致**评估虚高**。
- 后果：本地指标漂亮，真实场景拉胯。
- 防范：先切分、再做任何依赖全量数据的统计处理；验证/测试只在对应阶段使用。

### 5. 按用法区分而非名称

- 同一个数据集可以既当验证集又当测试集吗？**按"用途"区分**：反复用来调参的就是验证集；只跑一次做最终评估的才是测试集。名称可以改，用途不能混。

## 四、一句话总结

训练集改参数、验证集选方案、测试集定成绩；泛化是目标，数据泄漏是必须防的作弊漏洞——三集各司其职，成绩才可信。
