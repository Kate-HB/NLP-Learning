# 18 偏移映射与词 ID 映射

> 一句话：模型按 Token 干活，但标签按"词"或"字符"标注——偏移映射和词 ID 映射就是两种"坐标换算表"，解决不同坐标系之间的对齐问题。

## 一、直观含义

想象一个词被切成三个子词 Token，但只有"一个词的标签"。怎么把"词"的标签分给"Token"？又比如答案是"原文第 12~18 个字符"，模型却要预测"第 3 到第 4 个 Token"——怎么换算？答案是两张"换算表"：

- **偏移映射（Offset Mapping）**：记录每个 Token 对应原始文本的**字符起止位置**。
- **词 ID 映射（Word ID Mapping）**：记录每个子词 Token 属于原始的**哪个词**。

## 二、具体例子

"transformers 很棒"，假设子词切分为：

| Token | 字符起止 | 词 ID |
|---|---|---|
| transformers | (0, 12) | 0 |
| 很 | (13, 14) | 1 |
| 棒 | (14, 15) | 1 |
| `[SEP]` | — | None |

- 偏移映射：`很` 对应原文第 13~14 个字符；答案在原文第 14~15 字符 → 可推得对应 Token `棒`。
- 词 ID 映射："很""棒"都属于第 1 个词，标签应该一起处理。

## 三、技术要点（严谨部分）

### 1. 偏移映射（Offset Mapping）

- 记录每个 Token 对应原始文本中的**字符起止位置**。
- 用途：**抽取式问答**的答案常按字符位置标注，但模型预测的是 Token 起止位置 → 需要靠偏移映射在"字符坐标"和"Token 坐标"之间换算。

### 2. 词 ID 映射（Word ID Mapping）

- 记录每个子词 Token 属于原始的**哪个词**。
- 用途：**NER** 的标签往往按词标注，但模型按 Token 预测 → 需要知道"这组 Token 同属一个词"，从而分配标签。
- 特殊 Token（如 `[CLS]`、`[SEP]`）通常没有词 ID（记为 None）。

### 3. 这些映射解决什么问题

不同任务有不同的"标注坐标系"：

- NER：标签按**词**标 → 模型按 **Token** 预测。
- 抽取式问答：答案按**字符**标 → 模型预测 **Token** 起止位置。

映射表就是沟通两个坐标系的桥梁。具体怎么用，见 [61-子词标签对齐](61-子词标签对齐.md)（NER）和 [63-抽取式问答-生成式问答-与幻觉](63-抽取式问答-生成式问答-与幻觉.md)（QA）。

## 四、一句话总结

偏移映射是"Token ↔ 字符"的换算表，词 ID 映射是"Token ↔ 词"的换算表；有了它们，模型才能把"按词/按字符标注的答案"翻译成自己能预测的"Token 坐标"。
