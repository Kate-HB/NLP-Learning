# 09 Token 与 Tokenizer

> 一句话：Token 是模型实际处理的文本单位（不一定是"词"），Tokenizer 是"文本 ↔ Token ID"的完整转换系统。

## 一、直观含义

模型是数字机器，不能直接"读字"。所以第一步要把文本切成**小块**，再给每块编号。这里的小块就是 **Token**，切小块的动作叫**分词（Tokenization）**，负责干这活的整套流程叫 **Tokenizer**。

关键认知：**Token 不等于词**。一个罕见英文单词可能被切成好几个子词；中文一个常见词也可能由单字组成。模型看到的是 Token 序列，不是人脑子里那个"词序列"。

## 二、具体例子

- 英文："transformer" 可能被切成 `["trans", "##former"]` 两个 Token（`##` 表示"接着上一个词"）。
- 中文："自然语言处理" 常被按字切成 `["自", "然", "语", "言", "处", "理"]`。
- 标点、数字也会是独立 Token："你好！" → `["你", "好", "!"]`。
- 罕见单词："unbelievable" 若不在词表里，会拆成 `["un", "believ", "able"]`。

## 三、技术要点（严谨部分）

### 1. Token

- **Token**：模型实际处理的**离散文本单位**。
- 可能是一个字、一个完整单词、一个子词、一个标点，甚至一个字节片段。

### 2. Tokenization（分词）

- 把原始文本切分为 Token 的过程。

### 3. Tokenizer（完整的编码/解码系统）

Tokenizer 不止切文本，它负责一整套流程：

1. **规范化**：统一大小写、Unicode 等（详见 [14-规范化与预分词](14-规范化与预分词.md)）。
2. **切分**：把文本切成 Token。
3. **词表查找**：把每个 Token 映射成整数 ID。
4. **特殊 Token 添加**：自动加 `[CLS]`、`[SEP]` 等结构标记（详见 [15-特殊-Token](15-特殊-Token.md)）。
5. **坐标对应**：记录 Token 与原始字符位置的映射（详见 [18-偏移映射与词-ID-映射](18-偏移映射与词-ID-映射.md)）。
6. **解码**：把 Token ID 还原回文本。

### 4. 一个重要辨析

- **Tokenizer 负责文本 ↔ ID，不负责语义计算**。真正理解语义的是神经网络（Transformer Model）。
- 两者必须**共享同一套词表**：分词算法、特殊 Token、ID 编号必须一致，否则模型会"看不懂"输入（详见 [13-词表-Token-ID-与-OOV](13-词表-Token-ID-与-OOV.md)）。
- 两者必须**共享同一套词表**：分词算法、特殊 Token、ID 编号必须一致，否则模型会"看不懂"输入（详见 [13-词表-Token-ID-与-OOV](13-vocabulary-token-id-oov.md)）。

## 四、一句话总结

Token 是模型最小的处理单位、不一定是词；Tokenizer 是文本与 ID 之间完整转换的"翻译官"，它负责切分、编号、加标记，但语义理解要靠模型本体。
