# 66 向量索引、FAISS 与对称/非对称检索

> 一句话：向量索引是"快速找最近邻"的数据结构，FAISS 是其中最常用工具；对称检索是"相似的找相似的"，非对称检索是"短问题找长文档"。

- 先读 [65-向量空间-相似度度量-与检索](65-vector-space-similarity-retrieval.md)。

## 一、直观含义

数据一多，"把每个向量和查询向量都比一遍"就太慢了（线性扫描）。向量索引像图书馆的分类目录：把向量预先组织好，查的时候不用翻遍每本书，直接去对应的架子上找——快得多。

**FAISS** 就是这个"图书馆管理系统"，专门做高效向量相似度搜索。**它不生成向量、不理解文本**，只负责按已有的向量和距离规则找近邻。

对称 vs 非对称：

- **对称**：查询和候选长得差不多（句子找句子）。
- **非对称**：查询和候选长得不一样（短问题找长段落）——模型必须专门学会把不同形式但语义相关的文本映射到相近空间。

## 二、具体例子

- 用 BERT 把 100 万篇文档向量化 → 建立 FAISS 索引 → 查询向量进来，毫秒级返回 Top-5 最近邻。
- 客服机器人：用户问题"怎么退款"（短）→ 检索知识库里"退款政策说明"（长段落）——非对称检索。

## 三、技术要点（严谨部分）

### 1. 向量索引（Vector Index）

- 一种用于**快速近邻搜索**的数据结构。
- 典型做法：聚类（如 IVF 先粗分桶）＋ 压缩（如 PQ 量化），先定位候选桶，再在桶内精排。

### 2. 最近邻与近似最近邻

- **最近邻搜索（Nearest Neighbor Search）**：在大量向量中寻找与查询向量最接近的若干向量。
- **近似最近邻（Approximate Nearest Neighbor，ANN）**：**牺牲少量精确性**换取大规模搜索速度。实际系统中几乎都用 ANN。

### 3. FAISS

- **FAISS（Facebook AI Similarity Search）**：用于高效向量相似度搜索的工具。
- 不是生成模型，也不理解文本；只根据**已经计算好的向量和距离规则**寻找近邻。
- 常见使用链路：Embedding 全部算好 → `add_faiss_index()` 建索引 → `get_nearest_examples()` 取 Top-k。

### 4. 对称检索（Symmetric Semantic Search）

- 查询与候选文本**形式相似**，例如：句子找相似句子。
- 常用于：句子聚类、相似句去重。

### 5. 非对称检索（Asymmetric Semantic Search）

- 查询和文档**形式不同**，例如：短问题检索长段落。
- 模型需要专门学会把不同形式但语义相关的文本映射到**相近空间**。
- 常用于：RAG（问题 → 文档）、搜索。

### 6. 度量一致性（承接 65）

- 索引的度量必须与 Embedding 训练目标一致；用内积实现余弦要先把向量归一化。

## 四、一句话总结

向量索引和 FAISS 让"百万向量找最近邻"从秒级变毫秒级；对称检索处理"同类找同类"，非对称检索处理"问题找文档"——后者正是 RAG 的检索底座。
