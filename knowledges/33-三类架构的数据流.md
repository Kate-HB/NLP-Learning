# 33 三类架构的数据流

> 一句话：Encoder-only 一条输入路径，Decoder-only 一条带因果约束的路径，Encoder-Decoder 有两条路径（源序列进 Encoder、目标序列进 Decoder）——数据流不是同一条线。

## 一、直观含义

三种架构像三套不同分工的办公室：

- **Encoder-only（只读型）**：只有一条"读入"通道——把整段输入读进去，输出对输入的理解。典型：BERT。
- **Decoder-only（只写型）**：也只有一条通道，但带着"只能看过去"的规矩——按顺序一个字一个字往外写。典型：GPT。
- **Encoder-Decoder（读写型）**：有两条通道——一条把"源文本"读进去做理解，另一条照着理解"写"出目标文本。典型：T5、翻译模型。

## 二、具体例子

- **翻译 "I love NLP" → "我爱NLP"**：Encoder 读 "I love NLP" 得到源表示；Decoder 带着"我爱NLP"的开头 `<s>`，一步步生成"我爱NLP"。
- **情感分类**：只用 Encoder-only，读完整句 → 分类。
- **续写**：只用 Decoder-only，给 "NLP is" → 生成 "fun."。

## 三、技术要点（严谨部分）

### 1. Encoder-only 的数据流

- 只有一条输入路径：
  - 输入序列经过 Token 与位置表示 → 多层 Encoder → 上下文隐藏状态。
- 输出按任务使用：整段池化（分类）、逐 Token 分类（NER）、答案跨度预测（抽取式 QA）。

### 2. Decoder-only 的数据流

- 也只有一条序列路径，但使用**因果约束**：
  - 位置 i 的输入表示经过多层 Decoder → 得到 LM Logits → 用来预测**位置 i+1** 的 Token。
- 每一步的输出又追加回输入，继续下一步（自回归，见 [46-自回归生成](46-自回归生成.md)）。
- 每一步的输出又追加回输入，继续下一步（自回归，见 [46-自回归生成](46-autoregressive-generation.md)）。

### 3. Encoder-Decoder 的数据流（两条路径）

1. **源序列**经过自己的 Token Embedding 与位置表示，进入 Encoder，形成源序列隐藏状态。
2. **目标侧输入**也经过 Token Embedding 与位置表示，进入 Decoder。
   - 训练时：它是按目标位置**错开的正确目标**（右移，见 [51-Seq2Seq-Teacher-Forcing-与目标右移](51-Seq2Seq-Teacher-Forcing-与目标右移.md)）。
   - 训练时：它是按目标位置**错开的正确目标**（右移，见 [51-Seq2Seq-Teacher-Forcing-与目标右移](51-seq2seq-teacher-forcing-label-shift.md)）。
   - 推理时：它是起始 ID 与模型已经生成的 Token 前缀。
3. Decoder 先对目标前文做**因果自注意力**，再以当前 Decoder 状态为 Query、以 Encoder 输出为 Key 和 Value 做**交叉注意力**。
4. Decoder 最终隐藏状态通过 LM Head 产生目标词表 Logits。

### 4. 关键认知

> **Encoder-Decoder 不是"Encoder 输出直接变成文字"**，而是 Decoder 在源序列条件下逐步生成目标序列。

## 四、一句话总结

Encoder-only 是"读入型"单通道，Decoder-only 是"边看过去边写"单通道，Encoder-Decoder 是"先读源、再条件写"双通道——数据流不同，适用的任务就不同。
