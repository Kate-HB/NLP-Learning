# 58 解码策略：Sampling、Temperature、Top-k、Top-p 与惩罚

> 一句话：采样按概率随机选 Token 增加多样性，Temperature 调"分布陡峭度"，Top-k/Top-p 限制候选池，重复惩罚和长度惩罚修正生成偏好。

## 一、直观含义

- **Sampling（采样）**：不总选最火的字，而是按概率**抽签**——高分字中签概率大，低分字偶尔也能翻盘。多样性上来了，但可能更不稳定。
- **Temperature（温度）**：调节"抽签时偏不偏心"。温度低 → 更偏心高分的（更确定）；温度高 → 更平均（更随意）。
- **Top-k**：只在前 k 个最可能的字里抽——候选池固定大小。
- **Top-p**：只在前面的字**累计概率到 p** 时停下来，在集合里抽——候选池大小随分布自动变化。
- **重复惩罚 / 长度惩罚**：一个是"已经出现过的字扣分"，一个是"搜索时长短句的偏好"。

## 二、具体例子

概率分布：`{春:0.5, 风:0.3, 天:0.15, 震:0.05}`：

- Greedy：总是"春"。
- Sampling：70% 的次数出"春"，但也可能蹦出"震"（0.05）。
- Temperature 调低（如 0.3）："春"的概率被推到 0.9 以上，几乎必选。
- Temperature 调高（如 1.5）：分布被抹平，低概率字更容易被选中。
- Top-k=2：只在"春、风"里抽，"震"永远没机会。
- Top-p=0.8：累计到 0.8 时集合为 `{春,风}`（0.5+0.3=0.8），"震"被排除。

## 三、技术要点（严谨部分）

### 1. Sampling（采样）

- 按照概率分布**随机选择** Token，而不是始终取最大值。
- 优点：增加多样性。
- 缺点：提高不稳定和错误风险。

### 2. Temperature（温度）

- 在 Softmax **之前缩放 Logits**。
- 温度低 → 分布更尖锐 → 输出更确定。
- 温度高 → 分布更平坦 → 低概率 Token 更容易被选中。
- ⚠️ **温度不增加模型知识，只改变选择分布**。

### 3. Top-k Sampling

- 只保留概率最高的 **k 个** Token，再从中采样。
- 固定候选数量；但不同场景中第 k 个 Token 的实际概率可能差异很大（k=50 时分布可陡可平）。

### 4. Top-p Sampling（核采样，Nucleus Sampling）

- 选择**累计概率达到阈值 p** 的最小候选集合，再从中采样。
- 候选数量随分布变化：模型很确定时集合小，不确定时集合大。

### 5. 组合使用

- 实践中常组合：Top-p + Temperature 一起用（先缩放再截断再采样）。

### 6. 重复惩罚、长度惩罚与停止条件

- **重复惩罚（Repetition Penalty）**：降低已出现 Token 再次被选择的倾向，缓解循环重复。惩罚过强会破坏必须重复的名称、术语和语法结构——它只是解码控制，不能从根本上修复模型能力。
- **长度惩罚（Length Penalty）**：调整搜索时对长短序列的偏好，常用于 Beam Search（防止偏好短句或长句）。
- **停止条件（Stopping Criteria）**：规定何时结束生成——生成 EOS、达到最大新 Token 数、出现指定终止串。

## 四、一句话总结

采样靠"抽签"换多样性，Temperature 调偏心程度，Top-k/Top-p 管候选池大小，重复/长度惩罚修正偏好——这些只是生成时的"方向盘"，改不了模型本身的知识。
