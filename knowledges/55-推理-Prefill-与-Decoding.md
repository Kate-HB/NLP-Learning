# 55 推理：Prefill 与 Decoding

> 一句话：生成式推理分两阶段——Prefill 一次性算完提示词的隐藏状态和 KV，Decoding 再逐 Token 生成；"解码"这个词在 Transformer 里其实有三种不同含义。

- 先读 [46-自回归生成](46-autoregressive-generation.md)、[54-训练为什么并行-生成为什么串行](54-why-train-parallel-generate-serial.md)。

## 一、直观含义

生成一句话分两步：

1. **Prefill（预填充）**：把你给的提示词整段快速读完，把每个词算好、把"记忆"（KV）存好。这一步能并行。
2. **Decoding（解码/生成）**：然后一个字一个字往外蹦，每蹦一个字更新一次"记忆"。

一个容易踩的坑："解码"这个词有三种意思——Tokenizer 解码（ID→文字）、生成解码（按概率选 Token）、Transformer 的 Decoder 架构（网络结构）。千万别混。

## 二、具体例子

提示 "帮我写一首诗"：

- Prefill：把"帮我写一首诗"6 个 Token 一次算完，得到 6 份 KV 缓存。
- Decoding：第 1 步看 Logits → "春"；第 2 步带着"春"继续 → "风"；……直到生成 EOS 或到达长度上限。
- Tokenizer 解码：把 `[春,风,...]` 这些 ID 还原成中文文本显示给你。

## 三、技术要点（严谨部分）

### 1. 推理（Inference）

- 使用训练好的模型对新输入产生预测，**不更新模型参数**。

### 2. Prefill（预填充阶段）

- 一次处理**完整提示词**，计算所有输入 Token 的隐藏状态和注意力 Key、Value。
- 能在多个提示 Token 之间**并行**。
- 长提示仍会消耗大量计算和显存。

### 3. Decoding（解码阶段）

- **逐步生成新 Token**。每一步根据当前 Logits 选择一个或多个候选 Token，再继续下一步。
- 模型内部的一次完整循环：
  1. 从词表 Logits 选出 Token ID（策略见 [57](57-解码策略-Greedy-与-Beam-Search.md)、[58](58-解码策略-Sampling-Temperature-Top-k-Top-p.md)）。
  2. 把新 ID 追加到 ID 序列。
  3. 将新 ID 通过 Embedding 形成下一步输入表示。
  4. 结合历史 **KV Cache** 再计算下一组 Logits。
  5. 循环直到生成 EOS 或满足其他停止条件。
- 文本转换的细节：Tokenizer 可以同步把 ID 转成文本供用户查看，也可以生成结束后统一转换。**文本转换不是下一步神经网络计算的必要环节**——单个子词或字节 Token 未必能独立形成可读片段。

### 4. 三个"解码"的辨析

| 中文都叫"解码" | 对象 | 含义 |
|---|---|---|
| Tokenizer 解码 | Token ID | 还原成文本 |
| 生成解码 | 概率分布 | 按策略逐步选 Token |
| Transformer Decoder | 网络架构 | 因果自注意力等组成的结构 |

三者不等同（详见 [73-易混淆概念辨析-下](73-易混淆概念辨析-下.md)）。

## 四、一句话总结

Prefill 并行读完全部提示并算好记忆，Decoding 逐 Token 生成；"解码"在"ID还原、概率选词、Decoder架构"三种语境下含义完全不同。
