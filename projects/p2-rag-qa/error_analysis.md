# P2 错误分析

## 分析顺序

RAG 出错时先判断“正确证据是否进入 Top-k”，再判断“生成器是否正确使用证据”。若证据未召回，改提示词或换 LLM 没有意义。

| 现象 | 所属阶段 | 常见原因 | 改进 |
|---|---|---|---|
| Top-k 没有答案段落 | 检索 | chunk 不合适、问题与原文措辞差异大 | 调整切块，换 embedding，加入关键词检索 |
| 正确证据排在后面 | 排序 | 稠密向量区分度不足 | 增加 reranker，调大 Top-k 后重排 |
| 回答引用错误编号 | 生成 | LLM 未遵守提示词 | 校验引用编号，降低 temperature |
| 有关但证据不足仍回答 | 安全 | 阈值过低或生成模型利用外部记忆 | 提高阈值，强制拒答，人工复核 |
| 多个 chunk 内容重复 | 切块 | overlap 太大 | 减小 overlap，检索后去重 |

## 建议评测表

为每个问题记录：标准答案、标准来源、Top-k 是否召回、首条排名、回答正确性、引用正确性。至少分别准备直接事实题、跨 chunk 题、同义改写题和知识库外问题。

## 后续改进

- 用 BM25 + embedding 做混合检索，兼顾关键词和语义。
- 用 cross-encoder 对候选 chunk 二次排序。
- 大规模文档改用 FAISS，避免每次遍历全部向量。
- 对生成结果做引用存在性与来源一致性校验。
